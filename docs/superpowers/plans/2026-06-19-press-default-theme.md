# Theming Mechanism + Default Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a press site look finished out of the box via a named, adopter-owned theme — styled reference blocks, real typography, a page shell — without coupling the contract to any CSS framework.

**Architecture:** The engine ships one static stylesheet (`theme.css`) that styles everything through `var(--press-*)` custom properties; a pure helper (`buildThemeStyle`, mirroring `buildMetadata`) emits a `:root{ --press-* }` value block from the `theme` key resolved out of `press.config.ts`; the materialized `layout.tsx` loads three `next/font` families, imports `theme.css`, injects that `:root` block into `<head>`, and renders a header/main/footer shell. The CMS ships a `theme` content-type ("Themes" menu) seeded with one active "Default" — selection only, no value storage this phase.

**Tech Stack:** TypeScript (engine, hand-authored source), React Server Components / Next.js App Router (`next/font/google`), CSS custom properties (no Tailwind / CSS-in-JS / CSS Modules), Strapi 5 plugin (CMS content-type + Document Service seed), Vitest, Changesets.

## Global Constraints

These apply to **every** task below. Copied verbatim from the spec.

- **Token namespace is the contract.** The public surface is exactly two things: the `var(--press-*)` namespace (§4 table) and the single `:root{ --press-* }` injection point. `theme.css`, `layout.tsx`, the derivation logic, and the CMS `theme` content-type are Engine-owned and free to change.
- **`:root` is the only place token *values* enter the page** (§0). `buildThemeStyle` emits all value-bearing tokens; `theme.css` only *consumes* via `var()`. The one exception: font default values arrive via `next/font` variables on `<html>` (§6), so `buildThemeStyle` emits a `--press-font-*` token **only when the adopter overrides it**.
- **No new runtime dependency** is added to the engine or the materialized host beyond `next/font` (already part of Next.js) — AC8. No Tailwind, no CSS-in-JS, no CSS Modules.
- **Engine-owned files are regenerated by `upgrade`, never hand-edited** by the adopter. `theme.css`, `layout.tsx`, and the `theme` content-type schema must be byte-identical after an `upgrade`; `press.config.ts` is never rewritten (AC3, AC7).
- **`resolveConfig` and `buildThemeStyle` stay pure** — same input → same output, no I/O, no mutation, safe as immutable module constants under RSC/SSR. Mirror the existing `build-metadata.ts` discipline.
- **The active theme `name` is selection, not a token.** It is **never** emitted as a `var(--press-*)`; it is reflected only on `<html data-theme="…">`.
- **`ThemeName` is `'default'`** — the only embedded theme this phase. The selection mechanism exists so a second theme is additive, not breaking.
- **Exact Default-theme token values (§4):** colors `primary #119350`, `accent #D9A12C`, `secondary #3D5CC2`, `ink #142036`, `surface #FAF8F3`, `muted #7A7E89`, `danger #C0392B`, `onPrimary #FFFFFF`, `border rgba(20,32,54,0.12)`; radii `xs 6px, sm 10px, md 14px, lg 20px, pill 999px`; space scale `4 8 12 16 24 32 48 64 96` px (`--press-space-1..9`); type scale `kicker 12, sm 14, body 16, lg 18, h3 20, h2 28, h1 40` px; fonts `display Bricolage Grotesque, body Archivo, mono IBM Plex Mono`.

Create `packages/web/src/config/build-theme-style.ts`:

```ts
import type { ResolvedPressConfig, ThemeColors, ThemeFonts, ThemeRadius } from './types';
import { FIXED_TOKENS } from './default-theme';

/** Resolved colour key → CSS token suffix (`onPrimary` → `on-primary`). */
const COLOR_TOKENS: ReadonlyArray<readonly [keyof ThemeColors, string]> = [
  ['primary', 'primary'],
  ['accent', 'accent'],
  ['secondary', 'secondary'],
  ['ink', 'ink'],
  ['surface', 'surface'],
  ['muted', 'muted'],
  ['danger', 'danger'],
  ['onPrimary', 'on-primary'],
  ['border', 'border'],
];

const FONT_TOKENS: ReadonlyArray<readonly [keyof ThemeFonts, string]> = [
  ['display', 'display'],
  ['body', 'body'],
  ['mono', 'mono'],
];

const RADIUS_KEYS: ReadonlyArray<keyof ThemeRadius> = ['xs', 'sm', 'md', 'lg'];

/**
 * Emits the `:root{ --press-* }` value block from the resolved config — the
 * single injection point for token values (Spec §0). Mirrors `buildMetadata`:
 * pure, same input → same output, safe as an RSC/SSR module constant.
 *
 * Emits all colours, the engine-fixed space/type scales, and the radii. A font
 * token is emitted ONLY when the adopter overrode it (Spec §6) — otherwise
 * `theme.css`'s `var(--press-font-x, var(--press-font-x-default))` fallback uses
 * the `next/font` default. The theme `name` is NEVER emitted (it is selection,
 * reflected on `<html data-theme>` only).
 */
export function buildThemeStyle(resolved: ResolvedPressConfig): string {
  const { colors, fonts, radius } = resolved.theme;
  const lines: string[] = [];

  for (const [key, token] of COLOR_TOKENS) {
    lines.push(`  --press-color-${token}: ${colors[key]};`);
  }
  FIXED_TOKENS.space.forEach((value, i) => {
    lines.push(`  --press-space-${i + 1}: ${value};`);
  });
  for (const [name, value] of Object.entries(FIXED_TOKENS.text)) {
    lines.push(`  --press-text-${name}: ${value};`);
  }
  for (const key of RADIUS_KEYS) {
    lines.push(`  --press-radius-${key}: ${radius[key]};`);
  }
  lines.push(`  --press-radius-pill: ${FIXED_TOKENS.radiusPill};`);

  for (const [key, token] of FONT_TOKENS) {
    const value = fonts[key];
    if (value) lines.push(`  --press-font-${token}: ${value};`);
  }

  return `:root {\n${lines.join('\n')}\n}`;
}
```

```ts
import { describe, expect, it } from 'vitest';
import { seedDefaultTheme, THEME_UID } from './seed-default-theme';

/** Minimal Document-Service fake: a mutable count + a recording create(). */
function fakeStrapi(initialCount = 0) {
  let count = initialCount;
  const creates: Array<{ data: unknown }> = [];
  const strapi = {
    documents: (uid: string) => {
      expect(uid).toBe(THEME_UID); // helper must target the theme UID
      return {
        count: async () => count,
        create: async (params: { data: unknown }) => {
          count += 1;
          creates.push(params);
          return params.data;
        },
      };
    },
  } as any;
  return { strapi, creates, size: () => count };

    await seedDefaultTheme(strapi);
    await seedDefaultTheme(strapi);
```

```ts
import type { Core } from '@strapi/strapi';

/** UID of the engine's theme collection-type (plugin name `press-cms`). */
export const THEME_UID = 'plugin::press-cms.theme';

/**
 * Seeds exactly one active "Default" theme on a fresh DB (Spec §7). Idempotent:
 * if any theme already exists, it does nothing — a re-run (every bootstrap)
 * leaves exactly one active theme, never two. This owns the editorial SELECTION
 * surface only; token VALUES still come from press.config.ts (Spec §12 seam).
 */
export async function seedDefaultTheme(strapi: Core.Strapi): Promise<void> {
  const existing = await strapi.documents(THEME_UID).count({});
  if (existing > 0) return;
  await strapi.documents(THEME_UID).create({
    data: { name: 'Default', active: true },
  });
}
```
